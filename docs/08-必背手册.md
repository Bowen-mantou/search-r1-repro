## ★ 三、流水线五环节（各一句话）

1. **数据**：NQ+HotpotQA（打包数据集 → prepare_data.py 清洗成统一 JSONL）；
2. **蒸馏**：DeepSeek Chat 生成 397 条搜索-推理示范轨迹（模拟检索结果）；
3. **SFT 冷启动**：QLoRA（4-bit NF4，r=32）3 epochs——只教格式与流程；
4. **GRPO**：本地管线（QLoRA r=16，group=8，温度 1.0）+ 改进组件全开；
5. **veRL 迁移**：全参数 FSDP + vLLM + 自定义 AgentLoop，2×4090 环境调通 + TQ 瓶颈定量分析。

## 四、六个改进点速记

| 改进 | 一句话 | 证据数字 |
|---|---|---|
| 异常轨迹过滤 | 三类系统故障轨迹（空白/搜满无答/没搜格式错）排除出组统计量、advantage 置 0、不进训练序列 | 2.5% |
| LLDS | 单向似然保持正则 λ·Σₜmax(0, logπᵣ−logπᶿ)，防 LLD 死亡螺旋 | v2 低点恢复、不再永久崩 |
| PRM-Lite | 22 条规则过程奖励（12 罚 10 奖），cap [−0.2,+0.2] 防喧宾夺主 | 规则命中率可观测 |
| LATA | Âᵢ=(rᵢ−μ)/√Lᵢ，对长轨迹优势双向减震，剥离长度噪声 | √L 来自方差可加 |
| 5 搜索后端 | 统一 SearchClient 接口 + 运行时缓存 + 429 轮转 + 限速，换后端零改训练代码 | 知乎 0.68s/DeepSeek 1-3s/MiMo 6-14s |
| veRL 迁移 | TITO 协议 + response_mask + FSDP offload + probe 47 项 + TQ 分析 | 18.9GB/卡；51K ops vs 736/min |

## ★ 五、核心公式（符号约定：πᶿ=当前策略、π₀=旧策略、πᵣ=参考）

```
GRPO 优势：  Aᵢ = (rᵢ − μ) / (σ + ε)        组内归一化（排除异常后重算 μ/σ）
PPO clip：   L = −mean( min(ρ·A, clip(ρ,1±ε)·A) )，ρ = exp(logπᶿ − logπ₀)
LLDS：       P = λ · Σₜ max(0, log πᵣ(t) − log πᶿ(t))   单向地板，防变坏
LATA：       Âᵢ = (rᵢ − μ) / √Lᵢ           双向减震，剥离长度噪声
三档奖励：   1.0 对 / 0.0 错但格式对 / −0.1 格式错（normalize：小写去标点去冠词）
```

## 六、系统工程必背参数（四个"为什么"）

| 参数 | 值 | 一句话理由 |
|---|---|---|
| use_kl_loss | false | ref CPUOffload 在 torch 2.13 失效（实测常驻 8.46GB）+ 官方配方无 KL + LLDS 接替防崩 |
| max_num_seqs | 229 | Mamba cache block 上限（报错原文给数字） |
| update_weights_bucket | 512MB | 2048MB 超 torch 2.13 CUDA IPC 上限（INT_MAX=2GB−1） |
| optimizer/param offload | true | Adam 25.2GB 放 CPU：26.7GB❌ → 18.9GB✓，代价步时 +30-60s |

## ★★ 七、绝对不能说的话（口径纪律四条）

1. ❌ 「比原论文提升 27%」——**跨论文对比一律不做**；
2. ❌ 「veRL 训练没跑完 50 步」——veRL 部分只说「环境调通 + TQ 瓶颈定量分析」；
3. ❌ 「81.2% 是留出集评估/和 1.43% 同口径」——81.2% 是训练批次内指标（PyTRIO 日志、
   采样解码、训练池题目）；1.43% 是留出 dev 70 贪心；两者只能说方向性结论；
4. ❌ 「17 万训练样本」——正确口径「约 9 万唯一题目（文件 17 万行，含重复）」。

## ★ 八、高频追问标准答法（10 问，各 2-3 句）

1. **为什么 GRPO？** 三个约束交集：PPO 的 critic 在 2×4090 放不下（约 42GB）；
   DPO 表达不了在线搜索交互；任务可自动判分（EM+格式）满足 GRPO 前提。
2. **GRPO 的长度偏差？** 知道（Dr.GRPO 的发现），我用 LATA 用 √L 替代 σ 做双向
   减震，异常过滤防 σ 被污染——带处方用 GRPO。
3. **LLDS 为什么单向？** max(0,·) 只对"变坏"的 token 产生梯度；KL 双向会拖慢
   学习；v1 固定强度被优势项淹没、v2 比例缩放自动匹配——正则化强度必须同阶。
4. **异常轨迹 advantage 为什么是 0 不是 −1？** 0=中性不学；−1=把系统故障当策略
   错误惩罚。排除重算防止 −0.1 拉低均值虚高正常轨迹优势。
5. **TQ 瓶颈怎么定位的？** 51K 子操作/步 ÷ 736/min ≈ 70min 与实测吻合；换搜索
   后端（0.68s→6-14s）步时不变 = 交叉验证瓶颈在调度层。
6. **为什么关 KL？** 配方无 KL + ref offload 失效常驻 8.46GB + LLDS 接替防崩。
7. **为什么 √L 是标准差？** 方差可加（Var∝L）→ 开根号 std∝√L → 除 √L 把噪声
   拉回同一尺度（z-score 思想）。
8. **SFT 397 条够吗？** 教的是低维格式技能（loss 0.11 已饱和）；SFT 后 EM 1.43%、
   搜索 0 次证明它恰好只教会了格式；没做数据量消融，诚实承认。
9. **P9 规则怎么执行？** 结果块 ≥2 时：答案与第一块词重叠 >0.1 且与其余块 <0.02
   → 罚 0.03；纯字符串统计，启发式代理。
10. **为什么选 4B？** 先算显存再定模型：QLoRA 单卡 ~8GB；全参数 2×4090 offload
    后 18.9GB/卡。4B 是"预算内能跑全参数的最小可行解"。
